About this demo

Ask a question in plain English. Gemini writes one SQL query, the page checks that the query only reads data, runs it on a SQLite copy of a small online store, and, if it fails, sends the error back to Gemini to fix it (at most twice).

What do these options mean?

    Business rules sent to the model
    • Revenue is quantity × unit price, excluding cancelled and returned orders.
    • Today is 2026-10-30, so "last quarter" means July to September 2026.
    • Dates are ISO text (YYYY-MM-DD).

    Each viewer gets a fresh in-memory copy of the database, locked with PRAGMA query_only.

    How the schema linker works

    It matches the question against table names, column names, exact values in text columns and a short list of business terms, then adds the tables on the shortest declared foreign-key path between them. It never invents joins. Highlighted tables are the ones linked for the last question.

    If a query fails with "no such table" or "no such column", the linked set grows by one foreign-key hop before the repair (Linked mode only).

    Evaluation run: 15 test questions and 3 controlled repair tests
    How scoring works

    Reference SQL and expected results were fixed on 22 Nov 2026, before any LLM run. Expected results are computed live from the reference SQL. A result counts as correct when it has the same rows as the expected result (row order ignored, numbers rounded to 2 decimals, extra columns allowed). The built-in examples above are hand-written and are not part of this evaluation.

    Results are kept separately for each schema mode. Full schema is selected; switch the Schema control above to see or run the other mode. The Linking column is computed without the LLM: it checks whether the linker picked every table used by the reference SQL (strict recall).
